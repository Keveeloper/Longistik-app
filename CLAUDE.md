# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project state

Longistik is an **Ionic 9 + React 19 + Vite 8 + Capacitor 8** app (TypeScript) for cargo operations synced with Colombia's RNDC. Screens are built one at a time from the design PNGs. Done: company selector (`src/pages/CompanySelect`, no design PNG: built in the Login's style), Login (`src/pages/Login`) and Inicio (`src/pages/Home`), all against the real APIs (panel directory + the company's backend). Also done, **without design PNGs** (built in the app's style, so measure them against the designs when those arrive): the Manifiestos and Remesas tabs (`src/pages/Manifiestos`, `src/pages/Remesas`: lists, details, the full-screen manifiesto PDF viewer and the full-screen "Cumplir remesa"), and sobreanticipos (`src/pages/Sobreanticipos/MisSobreanticipos.tsx` at `/sobreanticipos`, opened from Inicio's "Mis sobreanticipos" row; the request form and list rows in `src/components/Sobreanticipos.tsx`; a "Sobreanticipos" section in the manifiesto detail, which `?seccion=sobreanticipos` scrolls to). Everything sobreanticipo is hidden without `sobreanticipos.solicitar`; a request `POST` is never retried or queued, since after a network error it may already exist (spec: `request/app-movil-sobreanticipos.md`). Also without PNGs: the bell (`src/pages/Notificaciones`, from Inicio's bell icon), push on the phone (`src/push/`) and trip tracking (`src/components/SeguimientoViaje.tsx` in the manifiesto detail, the "Viaje en curso" strip on Inicio and the one-tap `src/pages/Seguimiento/CompartirUbicacion.tsx`). The Novedades tab renders the `src/components/ComingSoon.tsx` placeholder. Inicio loads `GET /mobile/home/summary`; its "Cumplir remesa" action opens the Remesas tab and "Mis manifiestos activos" the Manifiestos tab. The backend contract for the app is `request/mobile-api.md`, a copy of the backend's `docs/mobile-api.md` (implemented in the app: P0 auth, P1 summary, P2 queries, P4 notifications + push, P5 sobreanticipos, P6 cumplido + manifiesto PDF, P7 trip tracking; backend-only so far: P3 catalogs (`catalogs.service.ts`, typed but unused), "Revisar y enviar" and the RNDC report; pending in the backend: create remesa/manifiesto, novedades). Backend detail docs copied next to it: `request/notificaciones-api.md`, `request/seguimiento-viaje-api.md`; requirements: `request/notificaciones-push.md`, `request/seguimiento-viaje.md`. No native platforms (`android/`, `ios/`) have been added yet.

```bash
npm run dev            # Vite dev server on http://localhost:5173
npm run build          # production build: tsc type-check, then vite build -> dist/
npm run build:test     # same, in the test environment (vite --mode test)
npm run preview        # serve the production build
npm run lint           # eslint (flat config, eslint.config.js)
npm run test.unit      # vitest (watch mode); add `-- --run` for a single pass
npx vitest run src/App.test.tsx          # single test file
npx vitest run -t "renders without crashing"   # single test by name
npm run dev:e2e        # dev server for Cypress on :5174, mode e2e (.env.e2e: test env, no local backend)
npm run test.e2e       # cypress run — requires `npm run dev:e2e` running on :5174
                       # from VS Code's terminal, unset ELECTRON_RUN_AS_NODE first or Cypress won't start
```

Capacitor (native): `npm run build` then `npx cap add android|ios` / `npx cap sync` / `npx cap open android|ios`. Capacitor serves from `dist/` (`webDir`). The `appId` is still the template default `io.ionic.starter` in `capacitor.config.ts` — change it before adding native platforms. The camera and geolocation plugins need their native permissions when the platforms are added: Android `CAMERA`, `ACCESS_COARSE_LOCATION` and `ACCESS_FINE_LOCATION` in `AndroidManifest.xml`; iOS `NSCameraUsageDescription` and `NSLocationWhenInUseUsageDescription` in `Info.plist`. Trip tracking only uses the location **while the app is in use**: never add background location. Push (`@capacitor-firebase/messaging`) needs the Firebase project of the final `appId`: `google-services.json` in `android/app/` (plus the Google services Gradle plugin) and Android 13+ `POST_NOTIFICATIONS`; on iOS `GoogleService-Info.plist`, the Push Notifications capability and Background Modes → Remote notifications, with the APNs key uploaded to Firebase.

## Architecture

- **Entry**: `src/main.tsx` mounts `App` under `React.StrictMode`. `src/App.tsx` calls `setupIonicReact()` and imports `src/theme/global.css` then `src/theme/variables.css` (unlayered Ionic `--ion-*` overrides).
- **Styling (Ionic + Tailwind v4 hybrid)**: `src/theme/global.css` imports Ionic's global CSS into `@layer ionic` and Tailwind's `theme`/`utilities` layers after it, so Tailwind utilities override Ionic defaults; unlayered CSS beats both. Tailwind **Preflight is deliberately omitted** (Ionic's `normalize.css` is the reset) and Ionic's optional utility CSS (`ion-padding`, flex-utils, etc.) is not loaded — use Tailwind for that. Ionic colors are exposed to Tailwind via `@theme inline` (`bg-primary`, `text-danger`, `bg-background`, `text-foreground`…); change colors in `variables.css`, not in `global.css`. Tailwind classes cannot reach inside Ionic's Shadow DOM: style `Ion*` components with their CSS custom properties (`--background`, `--color`…) or `::part`, and use Tailwind for your own markup and for positioning/sizing Ionic components. The Tailwind plugin is registered in `vite.config.ts`.
- **Visual system** (from the `Sistema visual` design file): brand colors live in `src/theme/variables.css` as Ionic colors: primary = verde acción `#3A8250` (buttons), secondary = petróleo `#2F6571` (links), tertiary = cielo `#79C4D7`, dark = tinta `#153741` (brand/text), medium = `#5A6B72` (secondary text), light = superficie `#F3F5F7` (blocks, secondary buttons), success `#3A8250`, warning `#D87029` (Pendiente RNDC), danger `#B3322E` (ERROR RNDC), plus `--app-line-color` `#DCE2E6` for hairlines. In Tailwind (`global.css`), colors use the design file's Spanish names: `tinta`, `verde`, `cielo`, `petroleo`, `superficie`, plus `muted`, `line` (input underline `#DCE2E6`), `divider` (section dividers, tab border and progress track `#EEF1F3`), `rndc-reportado`, `rndc-pendiente`, and `rndc-pendiente-soft` (pending callout `#FDF1E6`). Status badges ("Estados") are text/background pairs: `text-creada bg-creada-soft`, likewise `manifiesto`, `en-ruta`, `cumplido`, `activo`, `inactivo`, `error-rndc`. Type scale tokens carry their line height and weight: `text-display` 34/40 600, `text-title` 22/28 500, `text-body` 16/24 400, `text-caption` 13/18 400, `text-badge` 11/16 500 with tracking. `h1`/`h2` default to display/title through the `base` layer, so utilities still override them. Font is Figtree, bundled via `@fontsource-variable/figtree` (imported in `App.tsx`) so it works offline. The app is **light-only**: Ionic's dark palette is not loaded and `index.html` declares `color-scheme: light`. Ionic `md` mode uppercases buttons and adds letter-spacing, so design-matched buttons need `normal-case tracking-normal`.
- **Designs**: PNG mockups live outside the repo in `C:\Users\Kevind Ospina\Downloads\Longistik App Móvil-png` (`01 · Login` … `08 · Reportar novedad`, plus `Sistema visual`). They are 780×1688 = a 390×844 viewport at 2x, so divide pixel measurements by 2. Font sizes in the screens often differ from the type scale written in `Sistema visual`: the big figures are 31px with `tracking-[-1px]` (not 34), Inicio section titles are 18px (not 22), and body text is 14px. Measure against the PNG; don't assume the tokens. A workflow that has reached ±1px: screenshot the page in Cypress at 390×844 (stub the APIs with `cy.intercept` as in `auth.cy.ts`; simulate the iPhone safe areas with `--ion-safe-area-top: 47px` and `--ion-safe-area-bottom: 34px` on `<html>`), then compare element bounding boxes against the PNG divided by 2. Compare text widths with real DOM measurements (a Range over the element): canvas `measureText` and detached spans gave wrong numbers. Put temporary measurement specs/configs in `cypress/e2e/_*.cy.ts` / `cypress.visual.config.ts` and delete them afterwards.
- **Icons**: the designs use **Tabler Icons** (outline, 2px stroke) via the `@tabler/icons` package, rendered with `<IonIcon icon={...}>`, because Ionicons lacks several of them (truck, clipboard-check). All icons are registered in `src/icons.ts`. Variants that Tabler doesn't ship go in `src/assets/icons/` (e.g. `home-simple.svg`, Tabler's home without the door). Inside a 48px icon-only `IonButton`, the padding limits the icon's width, so a 26px icon needs 11px horizontal padding.
- **Routing**: `IonReactRouter` + `IonRouterOutlet` using **react-router v6** syntax (`<Route path element={...} />`, `<Navigate>`), not the v5 `component`/`Redirect` style found in many Ionic examples. Two outlet levels: the root outlet in `App.tsx` (`AppRoutes`) has static routes `/empresa` → `CompanySelect`, `/login` → `Login`, `/` → a bare `<Navigate>` to the guard's current stage, and `/*` → `src/layouts/TabsLayout.tsx`; (without the `/` route, the root URL mounts `TabsLayout` and its tab bar stays on top of the entry screens; a nested `<Navigate>` for `/` inside `TabsLayout` raced the guard and left Inicio stuck on top of the Login); `TabsLayout` holds a nested outlet with the tab routes (`/inicio`, `/manifiestos`, `/remesas`, `/novedades`) plus the bottom `IonTabBar`. Each `IonTabButton`'s `tab`/`href` must match a route path. Full-screen pages without the tab bar go in the root outlet. `IonReactRouter` forwards props to `BrowserRouter`; the v7 future flags are enabled there.
- **IonRouterOutlet pitfalls (both caused real bugs here)**: (1) the outlet keeps visited pages mounted but hidden and **reuses views by `path`**, so never render redirects from a component inside a route (a wrapper returning `<Navigate>` keeps firing from the hidden page, which caused an infinite redirect loop and a white flickering screen), and never swap which element a given path renders. A bare `<Navigate>` as the route `element` is fine, because Ionic unmounts it after redirecting. (2) Never conditionally mount/unmount an outlet: one mounted right after a navigation leaves its first page stuck with `ion-page-invisible` (blank screen).
- **Environments (test vs production)**: `VITE_APP_ENV`, set per Vite mode in the committed `.env.development` (`npm run dev`) and `.env.test` (`build:test`, also Vitest) = `test`, and `.env.production` (`build`) = `production`; anything else counts as production. Read it through `src/config/env.ts` (`APP_ENV`, `IS_TEST_ENV`), not `import.meta.env`. There is one panel for both environments, so the app filters the company directory: test builds list only `TEST_COMPANY_CODES` (`finaltest`, named "STAGING") and production hides them; a saved company not allowed in the current environment is dropped on launch. **Local backend**: `VITE_COMPANY_API_URL` (e.g. `http://localhost:3001` in `.env.development`) replaces the selected company's `apiUrl` for every company call; the company list still comes from the panel. Only the dev server honors it (`import.meta.env.DEV`), so builds can't point at localhost. A fixed badge (`src/components/EnvBadge.tsx`) shows "Test" and/or "Local" outside production. Cypress runs against `npm run dev:e2e` (mode `e2e`, `.env.e2e`: test environment, no local backend), so it doesn't depend on each developer's `.env.development`; its selectable company is STAGING.
- **Company (multi-tenant)**: each transport company runs its own Longistik backend. The app first lists active companies from the panel's public directory (`GET /api/public/companies`, spec in `request/mobile-companies-api.md`) via `src/services/companies.service.ts` (5-minute in-memory cache; base URL is `VITE_PANEL_API_URL`, else the proxy `/panel-api` in dev and `https://api.panel.longistik.com` in builds). The chosen `Company` (`code`, `name`, `apiUrl`, `webUrl`) lives in `src/store/company.store.ts` (persisted like the session). `clearCompany()` also logs out, because a session belongs to one company. `src/hooks/useCompanyRefresh.ts` re-fetches the list on every launch: if the saved `code` is gone (suspended) it calls `clearCompany()`, and if the company's data changed it updates the stored copy. Always use `apiUrl` as-is; never build URLs from `code`. The panel's CORS only allows `https://panel.longistik.com`, so dev goes through the Vite proxy `/panel-api` (`vite.config.ts`), and native builds rely on `CapacitorHttp` (enabled in `capacitor.config.ts`).
- **Auth/session**: `src/store/auth.store.ts` (Zustand + `persist`) holds `token`/`user`, persisted via `@capacitor/preferences` (`src/storage/preferencesStorage.ts`; native storage on device, localStorage on web). That storage is async, so `App.tsx` renders a spinner until both stores report `hasHydrated`, which keeps the guard from misrouting. The guard is `AppRoutes` in `App.tsx`: it sits outside the outlet, compares company + session with the active pathname, and `navigate(..., { replace: true })`s: no company → `/empresa`, company without a session → `/login`, signed-in users away from both entry screens (to `HOME_PATH` = `/inicio`). **Company/login/logout navigation is driven only by this guard**: components just call `setCompany()` / `clearCompany()` / `setSession()` / `logout()`. Don't also navigate imperatively, or the redirects race. `src/api/client.ts` is the shared axios instance: it uses the selected company's `apiUrl` as `baseURL`, adds `Authorization: Bearer <token>`, and, for requests that carried a token, calls `logout(notice)` on any 401 and on the 403s whose `code` is `USER_INACTIVE` or `APP_ACCESS_DENIED`; the Login shows that `notice`. A 403 `FORBIDDEN` (missing permission) must **not** end the session. It also exports `Page<T>` (the `{ items, page, pageSize, total }` listing envelope), `apiErrorCode()` and `apiErrorMessage()` (the backend's `{ statusCode, code, message }`). `src/services/auth.service.ts` logs in with `POST /mobile/auth/login` (`{ email, password }` → `{ accessToken, expiresIn, user }`; 401/403 carry a user-facing `message`), `GET /mobile/me` runs on launch and whenever the app returns to the foreground (`src/hooks/useSessionRefresh.ts` + `useAppResume.ts`, via `visibilitychange`), and "¿Olvidaste tu contraseña?" calls `POST /public/authentication/forgot-password`. `User` is `{ id, name, lastName, email, role, alcance, permisos, vehiculos }` (use `fullName()`). **Permissions and scope**: `alcance` is `todos` | `asignados` (only the user's assigned vehicles) | `ninguno`, and the backend filters every endpoint by it. Show or hide UI with `hasPermiso(user, code)` (codes in `Permiso`, e.g. Inicio's quick actions and "Revisar y enviar"); it tolerates sessions saved before `permisos` existed. Assignment rules are in `request/mobile-api.md` and `request/mobile-vehicle-assignment-api.md`; the company name comes from the company store. The auth store is persisted with `version: 1`, so older (mock) sessions are dropped. Company backend: "Backlogistic API" (NestJS), Swagger at `{apiUrl}/docs`, JSON at `/docs-json`. Outside React, read the store with `useAuthStore.getState()`.
- **Pages** follow the Ionic pattern `IonPage > IonContent` (plus `IonHeader` where the design has a toolbar), with a co-located `.css` file per page for Ionic internals (CSS variables, `::part`). Prefer Ionic components (`IonItem`, `IonProgressBar`, `IonAvatar`, `IonButton`, `IonTabBar`, `useIonToast`/`useIonActionSheet`) and use plain HTML + Tailwind only for very custom pieces. Add `ion-activatable` + `<IonRippleEffect />` for touch feedback on custom buttons. **Ionic's scoped component CSS (e.g. `ion-label`, `ion-input`) is unlayered, so it beats Tailwind utilities placed on those elements**, and `.item ion-label` inherits `font-size` from the item. Style such cases on the host from the page's `.css` file (e.g. set `font-size` on the `ion-item`). The tab bar (`src/layouts/TabsLayout.css`) is 56px plus the bottom safe area minus 7px (83px on an iPhone, as designed). Logout lives in the account action sheet opened from the Inicio avatar. Shared pieces for the list/detail pages: `AppHeader` (tinta toolbar, optional back button, search/segment slot), `EstadoBadge`/`RndcEstado`, `Aviso` callouts, and `src/utils/format.ts` (dates in America/Bogota, kg, pesos). Detail routes (`/manifiestos/:id`, `/remesas/:id`) live in the tabs outlet; the full-screen ones (`/manifiestos/:id/documento`, `/remesas/:id/cumplir`) in the root outlet, before `/*` (React Router ranks them as more specific). The outlet reuses a page for every `:id`, so `CumplirRemesa` keys its form by id and visit to start clean.
- **Cumplido (delivery) and offline use** (P6 of `request/mobile-api.md`): a driver cumple a remesa with photos (`@capacitor/camera` `takePhoto`; on the web, a file input), the phone's GPS (`@capacitor/geolocation`), who received it and the kg delivered; the backend saves that evidence and reports the RNDC cumplido with the times of the manifiesto's monitoring (the driver can adjust them). Every photo is stamped with remesa, date, time and coordinates (`src/offline/evidencia.ts`). **Every delivery is queued on the phone first** (`src/offline/cumplidos.ts` + `store/cumplidosQueue.store.ts`; photos in `@capacitor/filesystem`, `Directory.Data`) and sent with its queue id as `Idempotency-Key`, so retries never duplicate it. `src/hooks/useOfflineSync.ts` (mounted in `AppRoutes`) sends pending ones on sign-in, reconnection (`@capacitor/network`), resume and every minute; no response/5xx/401/403 keep it pending, other 4xx mark it `rechazado` for the user to discard. Queue items belong to a company + user. Lists and details fall back to the last response saved on the phone (`useCachedQuery`, `usePagedList` → `store/offlineCache.store.ts`, per company + user), with a "Sin conexión. Datos guardados el…" callout.
- **Notifications and push** (P4 of `request/mobile-api.md`): the bell (`/mobile/notificaciones`) is the source of truth; push is only the ring. Push only exists on the phone (`pushDisponible()` = native): `src/push/push.ts` loads `@capacitor-firebase/messaging` on demand (the web bundle doesn't carry Firebase), creates the Android channels `operacion`/`seguimiento`/`alertas`, and registers the FCM token with `POST /mobile/dispositivos`. The company backend asks the ConfigPanel to send (only the panel holds the Firebase credential). The permission is asked from Inicio's "Activar" card, never on launch ("Ahora no" hides it 30 days). `src/hooks/usePush.ts` (mounted in `AppRoutes`) keeps the token registered, shows notifications that arrive with the app open as a toast and, on tap, navigates with `rutaDeAviso()` (`src/push/avisos.ts`) unless `data.empresa`/`data.userId` belong to another session. A user-initiated logout must go through `cerrarSesion()` (it deletes the token from the backend while the session is still valid); `useAvisosStore` bumps when a notification arrives so the bell and Inicio reload.
- **Trip tracking** (P7, `request/seguimiento-viaje.md`): opt-in and pull-based, nothing runs in the background. The driver (alcance `asignados`) starts the trip from the manifiesto detail after accepting the purpose text (Ley 1581; the backend answers `409 CONSENTIMIENTO_REQUERIDO` without it), and the server asks for the location by push; tapping it opens `/seguimiento/:manifiestoId/compartir`, which shares it in one tap (`responderPedido()`), and with the app open it is answered automatically. Reports go through their own queue (`src/offline/seguimiento.ts` + `store/seguimientoCola.store.ts`, batches with idempotency keys, sent by `useOfflineSync`); without signal the trip saved under `VIAJE_ACTIVO_KEY` is used. Opening the app during an active trip sends an `oportunista` report only if the location permission was already granted (never a prompt). "Necesito ayuda" sends an `auxilio` report and offers `tel:123`.
- **Manifiesto PDF**: `GET /mobile/manifiestos/{id}/pdf` returns the web's PDF (with the RNDC QR) in base64 plus `valido`/`motivoNoValido` (fit to show at a roadside check). `src/offline/documentos.ts` saves it on the phone (`store/documentos.store.ts`) and, for drivers (alcance `asignados`), keeps a fresh copy of every active manifiesto in the background; the viewer opens the saved copy first, so it works without signal. It renders with pdf.js (`src/offline/pdfRender.ts`, loaded on demand): the **legacy** build plus a `Promise.withResolvers` polyfill that also runs inside the worker (`src/offline/pdf.worker.ts`), because drivers' phones may have an old WebView (Cypress's Electron 118 too).
- **Testing**: Vitest uses jsdom with globals enabled (config lives in `vite.config.ts` under `test`; setup in `src/setupTests.ts`). Cypress e2e specs live in `cypress/e2e/` (`auth.cy.ts` covers company selection and login, stubbing the panel (`cypress/fixtures/companies.json`) and the `/mobile` endpoints (`home-summary.json`, login, `me`) with `cy.intercept`, so it needs no real account. Hidden Ionic pages stay in the DOM, so scope `cy.contains` to the visible page when a text repeats (e.g. the company name on Login and Inicio). Text inside `ion-toast` is in its Shadow DOM (`.shadow().find('.toast-message')`); the default viewport is the 390×844 phone from the designs). Navigation tests must assert that the URL is **stable** (see `expectStableAt`: pathname and `history.length` unchanged after a wait) and that content is **`be.visible`**: a redirect loop can pass a plain pathname check mid-loop, and a page stuck at opacity 0 still passes `cy.contains`. Ionic doesn't reflect props like `type` onto the `ion-input` host and moves `aria-label` to the inner element, so select native elements (`input[autocomplete="username"]`, `input[type="password"]`). `ion-button` uses Shadow DOM, so reaching its inner `button` needs `{ includeShadowDom: true }`. `cumplido.cy.ts` covers the driver on the road: cumplir with photo (attach a file to `#_capacitor-camera-input-takephoto` with `selectFile`) and GPS (stub `navigator.geolocation.getCurrentPosition` in `onBeforeLoad`), the offline queue (`forceNetworkError`) and the PDF opened without signal. `sobreanticipos.cy.ts` covers requesting (form validation, `SALDO_NEGATIVO`), the disabled button with its reason, "Mis sobreanticipos" with filter and cancel, and hiding it all without the permission. An inline `IonModal` stays in the DOM (class `overlay-hidden`) after closing, so assert on its content instead. Ionic focuses an `ion-alert`'s wrapper once it finishes opening, which steals focus from an input typed into earlier: wait for `cy.focused()` to match `ion-alert .alert-wrapper` first. `scrollIntoView` doesn't scroll an `ion-content`: call its `scrollToBottom`/`scrollToPoint`. `seguimiento.cy.ts` covers starting a trip with consent, the one-tap share (also queued without signal and resent on resume), help, pause/resume and the bell; push itself can't run in Cypress (native only) and its routing is unit-tested in `src/push/avisos.test.ts`. `cypress/support/e2e.ts` stubs "no trip" for `/mobile/viajes/activo` and `/mobile/manifiestos/*/viaje` in every spec (a spec's own intercepts win). Every spec must stub the lists the tabs and the offline sync load (`/mobile/manifiestos?*`, `/mobile/remesas?*`): an unstubbed call reaches the real STAGING backend with a fake token, gets a 401 and ends the session. Ionicons loads each SVG the first time it is used, so wait for the icons' shadow `svg` before a screenshot. Adding a dependency makes Vite re-optimize and reload the page mid-test: re-run before trusting a failure.
- **Build**: `@vitejs/plugin-legacy` produces legacy-browser bundles per `.browserslistrc`.
