## Project state

Longistik is an **Ionic 9 + React 19 + Vite 8 + Capacitor 8** app (TypeScript) for cargo operations synced with Colombia's RNDC. Screens are built one at a time from the design PNGs. Done: Login (`src/pages/Login`), Inicio (`src/pages/Home`) and Manifiestos (`src/pages/Manifiestos`, a list with client-side search and estado filter), backed by a mock session. The Remesas and Novedades tabs render `src/components/ComingSoon.tsx` placeholders. Data is mocked: Home uses a hardcoded `summary` object and Manifiestos uses `src/data/manifiestos.mock.ts` (TODO: API). Shared pieces: `StatusBadge` (IonBadge with the "Estados" color pairs), `RndcStatus` (dot + "RNDC reportado"/"Pendiente RNDC"), and `src/utils/format.ts` (`formatCOP` → "$800.000", `formatShortDate` → "Ago 22"). No native platforms (`android/`, `ios/`) have been added yet.

## Commands

```bash
npm run dev            # Vite dev server on http://localhost:5173
npm run build          # tsc type-check, then vite build -> dist/
npm run preview        # serve the production build
npm run lint           # eslint (flat config, eslint.config.js)
npm run test.unit      # vitest (watch mode); add `-- --run` for a single pass
npx vitest run src/App.test.tsx          # single test file
npx vitest run -t "renders without crashing"   # single test by name
npm run test.e2e       # cypress run — requires `npm run dev` running on :5173
```

Capacitor (native): `npm run build` then `npx cap add android|ios` / `npx cap sync` / `npx cap open android|ios`. Capacitor serves from `dist/` (`webDir`). The `appId` is still the template default `io.ionic.starter` in `capacitor.config.ts` — change it before adding native platforms.

## Architecture

- **Entry**: `src/main.tsx` mounts `App` under `React.StrictMode`. `src/App.tsx` calls `setupIonicReact()` and imports `src/theme/global.css` then `src/theme/variables.css` (unlayered Ionic `--ion-*` overrides).
- **Styling (Ionic + Tailwind v4 hybrid)**: `src/theme/global.css` imports Ionic's global CSS into `@layer ionic` and Tailwind's `theme`/`utilities` layers after it, so Tailwind utilities override Ionic defaults; unlayered CSS beats both. Tailwind **Preflight is deliberately omitted** (Ionic's `normalize.css` is the reset) and Ionic's optional utility CSS (`ion-padding`, flex-utils, etc.) is not loaded — use Tailwind for that. Ionic colors are exposed to Tailwind via `@theme inline` (`bg-primary`, `text-danger`, `bg-background`, `text-foreground`…); change colors in `variables.css`, not in `global.css`. Tailwind classes cannot reach inside Ionic's Shadow DOM: style `Ion*` components with their CSS custom properties (`--background`, `--color`…) or `::part`, and use Tailwind for your own markup and for positioning/sizing Ionic components. The Tailwind plugin is registered in `vite.config.ts`.
- **Visual system** (from the `Sistema visual` design file): brand colors live in `src/theme/variables.css` as Ionic colors: primary = verde acción `#3A8250` (buttons), secondary = petróleo `#2F6571` (links), tertiary = cielo `#79C4D7`, dark = tinta `#153741` (brand/text), medium = `#5A6B72` (secondary text), light = superficie `#F3F5F7` (blocks, secondary buttons), success `#3A8250`, warning `#D87029` (Pendiente RNDC), danger `#B3322E` (ERROR RNDC), plus `--app-line-color` `#DCE2E6` for hairlines. In Tailwind (`global.css`), colors use the design file's Spanish names: `tinta`, `verde`, `cielo`, `petroleo`, `superficie`, plus `muted`, `line` (input underline `#DCE2E6`), `divider` (section dividers, tab border and progress track `#EEF1F3`), `rndc-reportado`, `rndc-pendiente`, and `rndc-pendiente-soft` (pending callout `#FDF1E6`). Status badges ("Estados") are text/background pairs: `text-creada bg-creada-soft`, likewise `manifiesto`, `en-ruta`, `cumplido`, `activo`, `inactivo`, `error-rndc`. Type scale tokens carry their line height and weight: `text-display` 34/40 600, `text-title` 22/28 500, `text-body` 16/24 400, `text-caption` 13/18 400, `text-badge` 11/16 500 with tracking. `h1`/`h2` default to display/title through the `base` layer, so utilities still override them. Font is Figtree, bundled via `@fontsource-variable/figtree` (imported in `App.tsx`) so it works offline. The app is **light-only**: Ionic's dark palette is not loaded and `index.html` declares `color-scheme: light`. Ionic `md` mode uppercases buttons and adds letter-spacing, so design-matched buttons need `normal-case tracking-normal`.
- **Designs**: PNG mockups live outside the repo in `C:\Users\Kevind Ospina\Downloads\Longistik App Móvil-png` (`01 · Login` … `08 · Reportar novedad`, plus `Sistema visual`). They are 780×1688 = a 390×844 viewport at 2x, so divide pixel measurements by 2. Font sizes in the screens often differ from the type scale written in `Sistema visual`: the big figures are 31px with `tracking-[-1px]` (not 34), Inicio section titles are 18px (not 22), and body text is 14px. Measure against the PNG; don't assume the tokens. A workflow that has reached ±1px: screenshot the page in Cypress at 390×844 (the auth flow logs in with the mock; simulate the iPhone safe areas with `--ion-safe-area-top: 47px` and `--ion-safe-area-bottom: 34px` on `<html>`), then compare element bounding boxes against the PNG divided by 2. Compare text widths with real DOM measurements (a Range over the element): canvas `measureText` and detached spans gave wrong numbers. Put temporary measurement specs/configs in `cypress/e2e/_*.cy.ts` / `cypress.visual.config.ts` and delete them afterwards.
- **Icons**: the designs use **Tabler Icons** (outline, 2px stroke) via the `@tabler/icons` package, rendered with `<IonIcon icon={...}>`, because Ionicons lacks several of them (truck, clipboard-check). All icons are registered in `src/icons.ts`. Variants that Tabler doesn't ship go in `src/assets/icons/` (e.g. `home-simple.svg`, Tabler's home without the door). Inside a 48px icon-only `IonButton`, the padding limits the icon's width, so a 26px icon needs 11px horizontal padding.
- **Routing**: `IonReactRouter` + `IonRouterOutlet` using **react-router v6** syntax (`<Route path element={...} />`, `<Navigate>`), not the v5 `component`/`Redirect` style found in many Ionic examples. Two outlet levels: the root outlet in `App.tsx` (`AppRoutes`) has static routes `/login` → `Login` and `/*` → `src/layouts/TabsLayout.tsx`; `TabsLayout` holds a nested outlet with the tab routes (`/inicio`, `/manifiestos`, `/remesas`, `/novedades`) plus the bottom `IonTabBar`. Each `IonTabButton`'s `tab`/`href` must match a route path. Full-screen pages without the tab bar go in the root outlet. `IonReactRouter` forwards props to `BrowserRouter`; the v7 future flags are enabled there.
- **IonRouterOutlet pitfalls (both caused real bugs here)**: (1) the outlet keeps visited pages mounted but hidden and **reuses views by `path`**, so never render redirects from a component inside a route (a wrapper returning `<Navigate>` keeps firing from the hidden page, which caused an infinite redirect loop and a white flickering screen), and never swap which element a given path renders. A bare `<Navigate>` as the route `element` is fine, because Ionic unmounts it after redirecting. (2) Never conditionally mount/unmount an outlet: one mounted right after a navigation leaves its first page stuck with `ion-page-invisible` (blank screen).
- **Auth/session**: `src/store/auth.store.ts` (Zustand + `persist`) holds `token`/`user`, persisted via `@capacitor/preferences` (`src/storage/preferencesStorage.ts`; native storage on device, localStorage on web). That storage is async, so `App.tsx` renders a spinner until `hasHydrated` is true, which keeps the guard from misrouting. The guard is `AppRoutes` in `App.tsx`: it sits outside the outlet, compares the session with the active pathname, and `navigate(..., { replace: true })`s guests to `/login` and signed-in users away from `/login` (to `HOME_PATH` = `/inicio`). **Login/logout navigation is driven only by this guard**: components just call `setSession()` / `logout()`. Don't also navigate imperatively, or the redirects race. `src/api/client.ts` is the shared axios instance: it adds `Authorization: Bearer <token>` and calls `logout()` on any 401. `src/services/auth.service.ts` uses a mock whenever `VITE_API_URL` is empty (see `.env.example`); the mock accepts any credentials except the password `error`. Outside React, read the store with `useAuthStore.getState()`.
- **Pages** follow the Ionic pattern `IonPage > IonContent` (plus `IonHeader` where the design has a toolbar), with a co-located `.css` file per page for Ionic internals (CSS variables, `::part`). Prefer Ionic components (`IonItem`, `IonProgressBar`, `IonAvatar`, `IonButton`, `IonTabBar`, `useIonToast`/`useIonActionSheet`) and use plain HTML + Tailwind only for very custom pieces. Add `ion-activatable` + `<IonRippleEffect />` for touch feedback on custom buttons. **Ionic's scoped component CSS (e.g. `ion-label`, `ion-list`, `ion-searchbar`, `ion-input`) is unlayered, so it beats Tailwind utilities placed on those elements**, and it is injected after the page CSS, so it also wins ties. Known cases:
  - `.item ion-label` inherits `font-size` from the item, so set it on the `ion-item`.
  - `.list-md` keeps its 8px padding despite `py-0`, so use `ion-list.my-class { padding: 0 }`.
  - The searchbar's internals need selectors like `ion-searchbar.my-class .searchbar-input`.
  - Inside `IonLabel`, use `div`/`span`, not `h2`/`p`, because Ionic restyles those.

  In contrast, **shadow-DOM components (`IonBadge`, `IonChip`, `IonButton`) do take Tailwind classes on the host**: outer styles beat their `:host` rules. With Ionic custom elements, pass ARIA booleans as strings (`aria-pressed={selected ? 'true' : 'false'}`), because React 19 doesn't serialize `true` for custom elements. The tab bar (`src/layouts/TabsLayout.css`) is 56px plus the bottom safe area minus 7px (83px on an iPhone, as designed). Logout lives in the account action sheet opened from the Inicio avatar. The mock login always returns the demo user "Andrés Rojas" / "Transportes del Valle S.A.S." (`User` has a `company` field).
- **Testing**: Vitest uses jsdom with globals enabled (config lives in `vite.config.ts` under `test`; setup in `src/setupTests.ts`). Cypress e2e specs live in `cypress/e2e/` (`auth.cy.ts` covers the login flow, `manifiestos.cy.ts` covers search and filters; `cy.login()` in `cypress/support/commands.ts` logs in through the UI with the mock; the default viewport is the 390×844 phone from the designs). Navigation tests must assert that the URL is **stable** (see `expectStableAt`: pathname and `history.length` unchanged after a wait) and that content is **`be.visible`**: a redirect loop can pass a plain pathname check mid-loop, and a page stuck at opacity 0 still passes `cy.contains`. Ionic doesn't reflect props like `type` onto the `ion-input` host and moves `aria-label` to the inner element, so select native elements (`input[autocomplete="username"]`, `input[type="password"]`). `ion-button` uses Shadow DOM, so reaching its inner `button` needs `{ includeShadowDom: true }`.
- **Build**: `@vitejs/plugin-legacy` produces legacy-browser bundles per `.browserslistrc`.
